With a caller count named i, the condition becomes i < i; no rows are deleted, but the outer pointer array is freed and set to NULL. A tracked-element reproduction allocated two rows, called SAFE_DELETE_2D_ARRAY(p, i), and confirmed that the rows remained live after the outer deletion. Saved row pointers were explicitly cleaned up before the regression assertion failed, so the diagnostic itself did not intentionally abandon their allocations.

A pointer argument named i also collides with that local name. Indexed owner expressions referring to a caller i are evaluated again under the macro's loop binding, and row-count/pointer expressions can be evaluated repeatedly. These are argument-capture/evaluation defects in the helper interface; no observed Civ4 runtime incident or already-integrated consumer is claimed.

[Committed correction 3576901a3a6c78fbc1116eb28a30746f5682bef9](https://github.com/SuperXANA/AdvCiv/commit/3576901a3a6c78fbc1116eb28a30746f5682bef9) adds [FDelete2DArray at CvMemoryManager.h:26](https://github.com/SuperXANA/AdvCiv/blob/3576901a3a6c78fbc1116eb28a30746f5682bef9/CvGameCoreDLL/CvMemoryManager.h#L26). Its pointer reference retains ownership of the exact caller-selected lvalue, and its int row count is captured by value before the function body. The original macro syntax and do/while(false) semicolon/if-else behavior remain, forwarding to the globally qualified helper. Each row is deleted with its own element type through SAFE_DELETE_ARRAY, followed by the outer pointer array; the caller's owner is nulled. Null owners, null rows and zero rows remain supported. The original XANA explanatory comment is retained, with dated markers around the refinement.

Pointer and count argument expressions now each evaluate once, including when the selected pointer is NULL. Their relative evaluation order remains the normal unspecified C++03 function-argument order; callers must not depend on an ordering between side effects. The supplied count must be the actual nonnegative row count representable by an engine int, and row/outer allocations must match delete[]. This helper cannot discover allocation extents or make an invalid pointer/count pair safe.

No class layout, save format, exception recovery or independent feature integration is introduced.
